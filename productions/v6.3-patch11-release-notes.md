## 发布目标

将技术专家组的提示词利用率提升方案适配到现有系统，解决 S05 仅 349 字符的问题，将提示词利用率从约 67% 提升到 90%+，稳定输出 889-988 字符。

---

## 改动清单

### 1. 新建 `systems/char-counter.js`（真实字符计数）
- **功能**: 使用 `[...str].length` 替代 `String.length`，准确计算中文字符数
- **方法**: `count()`、`truncate()`、`utilization()`、`countWeighted()`（兼容旧日志）
- **导出**: `{ CharCounter, charCounter }`

### 2. 新建 `systems/prompt-dedupe.js`（字段去重）
- **功能**: 防止 Scene/Action 等字段重复（相似度 >72% 自动重写）
- **方法**: `jaccardSimilarity()`（基于词集合的相似度计算）、`dedupeShotFields()`
- **重写策略**: Scene/Action 重复 → 重写 Action 为角色表演；Camera/Scene 重复 → 重写为通用运镜；Lighting/Scene 重复 → 重写为通用灯光
- **导出**: `{ dedupeShotFields, jaccardSimilarity }`

### 3. 修改 `scripts/promptforge-director-worker.js`（动态补齐）
- **新增**: `calibratePrompt()` 函数（动态补齐到目标长度 889-988）
- **新增**: `fillPromptToTarget()` 函数（最终兜底补齐）
- **动态补齐素材库**: 世界观、材质、灯光、相机、镜头运动、环境、负面约束、渲染等 8 个维度
- **逻辑**: LLM 输出后自动检查长度，如果 < 889 则按目标差距填充素材，确保内容不重复，最终硬截断到 988

### 4. 修改 `systems/nirath-master-pipeline.js`（最终兜底）
- **引入**: `charCounter` 和 `dedupeShotFields` 模块
- **新增**: `finalFillPrompt()` 方法（兜底补齐到 889-988 字符）
- **位置**: Stage 11 渲染引擎最终返回前调用 `finalFillPrompt`
- **补齐逻辑**: 从主链路提取世界观、材质、灯光等维度，动态填充，去重检查，硬截断到 988

### 5. 修改 `systems/promptforge-director.js`（强化 LLM system prompt）
- **目标长度调整**: 从 796-831 改为 **889-988**
- **字段长度分配**:
  - 【视觉】120-180 字符（核心画面描述）
  - 【镜头时间轴】100-160 字符（运镜设计）
  - 【环境音效】60-100 字符（声音设计）
- **禁止重复约束**: 每个字段必须独立，不得与 Scene 或 Action 重复
- **禁止分析**: 只输出一版最终稿，不写思考过程
- **动态计算**: `targetMin = 889 - SYSTEM_TEMPLATE_LEN`，`targetMax = 988 - SYSTEM_TEMPLATE_LEN`
- **扩展逻辑**: `_assembleFullPrompt` 添加扩展逻辑（如果组装后 < 889，自动扩展）
