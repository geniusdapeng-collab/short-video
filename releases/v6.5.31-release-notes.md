- **版本**: v6.5.31
- **日期**: 2026-06-08
- **提交**: `7ab8a1e`
- **修复目标**: 根治 prompt 中 `[object Object]` 残留问题，质量分从 75 → 90+
- **前一版本**: v6.5.30 (commit `63c65ec`)

## 问题描述
预生产输出中 prompt 字段出现 `[object Object]` 残留，导致质量分卡在 75 (C 级 WARN)。

示例污染：
```
电影级镜头, 开场介绍, realistic scene, [object Object], 电影级镜头, 
natural expression and [object Object], natural expression, static shot
```

## 根因分析
**核心问题**: `characterPromptBuilder.build()` 返回的是对象 `{ prompt, layers, stats, negativePrompt }`，但 `stageCharacters` 方法直接将整个对象存为 `char.prompt`，而不是提取其中的 `.prompt` 字符串字段。

当 `buildBasePrompt` 使用 `char.prompt` 进行字符串拼接时：
- `typeof char?.prompt === 'string'` → false (因为是对象)
-  fallback 到 `String(char?.prompt)` → `'[object Object]'`
- 这个污染字符串通过 `channelSeparator` 和 `tierBuilder` 传播到最终 prompt

**影响链路**:
1. `stageCharacters` → 存储对象而非字符串
2. `buildBasePrompt` → `char.prompt` 被强制转字符串 → `[object Object]`
3. `channelSeparator._buildCharacterVisual` → `[object Object]` 作为 appearance 注入
4. `tierBuilder._buildTier1` → `[object Object]` 作为 subject 注入
5. 最终 prompt 包含多处 `[object Object]`

**关联问题**: `stageRender` Nirath 路径中 `buildMinimal(char, ...)` 传入了 wrapper 对象（含 `profile`/`prompt` 而非 `visualIdentity`/`name`），导致 `buildMinimal` 只能返回 `'角色'` 而非真实特征描述。

## 修复清单

### 1. `nirath-master-pipeline.js` - `stageCharacters` (line ~1230)
**修复**: 从 `build()` 返回对象中提取 `.prompt` 字符串
```javascript
charPrompt = this.modules.characterPromptBuilder.build(charProfile);
// v6.5.31-fix: build() returns {prompt, layers, stats, negativePrompt}, extract the string
if (charPrompt && typeof charPrompt === 'object' && charPrompt.prompt) {
  charPrompt = charPrompt.prompt;
}
```

### 2. `nirath-master-pipeline.js` - `stageRender` Nirath 路径 (line ~3937)
**修复**: 传入 `char.profile` 给 `buildMinimal` 而非 wrapper 对象
```javascript
// v6.5.31-fix: pass char.profile (the actual character profile) instead of wrapper
const minimal = this.modules.characterPromptBuilder.buildMinimal(char.profile || char, { maxChars: 30 });
characterProfiles[charId] = minimal;
// fallback
characterProfiles[charId] = char.profile?.name || charId;
```

### 3. `nirath-master-pipeline.js` - `buildBasePrompt` (line ~5554/5586)
**修复**: 防御式对象提取，防止任何残留对象穿透
```javascript
// v6.5.31-fix: defensive extraction - handle both string and object prompts
let promptText = char?.prompt;
if (promptText && typeof promptText === 'object') {
  promptText = promptText.prompt || promptText.description || promptText.name || String(cid);
}
return { name: cid, appearance: (typeof promptText === 'string' ? promptText.substring(0, 50) : String(promptText || cid)).substring(0, 50) };
```

## 经验教训
1. **API 返回类型陷阱**: 看似返回 "prompt" 的方法可能返回包含 prompt 的对象，调用方必须明确提取目标字段
2. **TypeScript 缺失代价**: 无类型检查时，`typeof x === 'string'` 的 fallback 路径 (`String(x)`) 是最后防线，但对象强制转字符串会产生 `[object Object]` 这种隐蔽污染
3. **防御式编程原则**: 在 prompt 字符串拼接的所有入口点做对象类型检查，而非仅信任上游返回类型
