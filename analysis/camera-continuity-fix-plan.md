# 首尾帧 + 运镜衔接 链路机制修复方案

## 问题一：首尾帧没有生效

### 根本原因
当前提交方式：**并发提交**所有镜头，每个镜头独立渲染，没有关联。

```
❌ 错误流程：
S01提交 → S02提交 → S03提交（同时）
     ↓         ↓         ↓
  独立渲染   独立渲染   独立渲染（无关联）
```

**正确流程**：
```
✅ 正确流程：
S01提交 → 等待完成 → 提取S01尾帧 → S02提交（含S01尾帧作为first_frame）
  → 等待完成 → 提取S02尾帧 → S03提交（含S02尾帧作为first_frame）
```

### 技术实现
1. **串行渲染引擎**：`sequential-render-engine.js`
   - 按镜头顺序逐个提交
   - 每个镜头渲染完成后自动下载视频
   - 使用ffmpeg提取最后一帧（尾帧）
   - 将尾帧转为base64，作为下一镜头的first_frame

2. **尾帧提取**：
   ```bash
   ffmpeg -i video.mp4 -ss 00:00:04.5 -vframes 1 last_frame.png
   ```

3. **API调用**：
   ```javascript
   content.push({
     type: 'image_url',
     image_url: { url: 'data:image/png;base64,...' },
     role: 'first_frame'  // 关键：role必须是first_frame
   })
   ```

### 修复方案
1. 创建 `sequential-render-engine.js` 串行渲染引擎
2. 修改提交脚本，支持串行模式
3. 自动提取尾帧并传递

## 问题二：相邻镜头运镜衔接

### 影视创作原理

运镜衔接的核心原则：**避免重复感，创造视觉节奏**。

#### 1. 推镜头（Push In）的衔接规则

**推镜头** = 镜头向主体靠近，制造紧张感/聚焦感。

| 前一镜头结束 | 后一镜头开始 | 效果 | 评价 |
|------------|------------|------|------|
| 推镜头 | 推镜头 | 重复感，视觉疲劳 | ❌ **禁止** |
| 推镜头 | 拉远（Pull Out） | 对比，呼吸感 | ✅ **推荐** |
| 推镜头 | 环绕（Orbit） | 层次变化，立体感 | ✅ **推荐** |
| 推镜头 | 俯冲（Dive） | 动态转换，冲击感 | ✅ **可用** |
| 推镜头 | 定格（Freeze） | 停顿，强调 | ✅ **可用** |
| 推镜头 | 平移（Pan） | 视线转移 | ⚠️ 一般 |

#### 2. 拉远（Pull Out）的衔接规则

| 前一镜头结束 | 后一镜头开始 | 效果 | 评价 |
|------------|------------|------|------|
| 拉远 | 拉远 | 重复感 | ❌ **禁止** |
| 拉远 | 推进 | 对比，紧张感 | ✅ **推荐** |
| 拉远 | 俯冲 | 视角转换 | ✅ **推荐** |
| 拉远 | 环绕 | 空间展示 | ✅ **可用** |

#### 3. 环绕（Orbit）的衔接规则

| 前一镜头结束 | 后一镜头开始 | 效果 | 评价 |
|------------|------------|------|------|
| 环绕 | 环绕 | 重复感 | ❌ **禁止** |
| 环绕 | 推进 | 从外到内，聚焦 | ✅ **推荐** |
| 环绕 | 拉远 | 从内到外，全局 | ✅ **推荐** |
| 环绕 | 俯冲 | 视角突变 | ✅ **可用** |
| 环绕 | 定格 | 停顿，强调 | ✅ **可用** |

#### 4. 俯冲（Dive）的衔接规则

| 前一镜头结束 | 后一镜头开始 | 效果 | 评价 |
|------------|------------|------|------|
| 俯冲 | 俯冲 | 重复感 | ❌ **禁止** |
| 俯冲 | 悬浮/环绕 | 减速，稳定 | ✅ **推荐** |
| 俯冲 | 推进 | 加速，聚焦 | ✅ **可用** |
| 俯冲 | 定格 | 突然停止 | ⚠️ 突兀 |

#### 5. 定格（Freeze）的衔接规则

| 前一镜头结束 | 后一镜头开始 | 效果 | 评价 |
|------------|------------|------|------|
| 定格 | 定格 | 重复感 | ❌ **禁止** |
| 定格 | 推进 | 从静到动，启动 | ✅ **推荐** |
| 定格 | 拉远 | 从静到动，展开 | ✅ **推荐** |
| 定格 | 俯冲 | 从静到动，冲击 | ✅ **可用** |

### 运镜衔接规则总结

```
运镜衔接矩阵（✅ 推荐 / ⚠️ 一般 / ❌ 禁止）

          后一镜头开始
          推   拉   环   俯   定
前一   推  ❌   ✅   ✅   ✅   ✅
结束   拉  ✅   ❌   ✅   ✅   ⚠️
       环  ✅   ✅   ❌   ✅   ✅
       俯  ✅   ⚠️   ✅   ❌   ⚠️
       定  ✅   ✅   ⚠️   ✅   ❌
```

### 核心原则
1. **禁止相同运镜连续使用**（推→推、拉→拉、环→环等）
2. **推之后跟拉或环绕**（创造对比）
3. **拉之后跟推或俯冲**（创造紧张感）
4. **环绕之后跟推或拉**（从外到内或从内到外）
5. **俯冲之后跟悬浮或环绕**（减速稳定）
6. **定格之后跟动态运镜**（从静到动）

### 三镜头运镜节奏设计（15秒短片）

```
S01 钩子（3秒）：环绕推进 → 急拉俯冲 → 瞳孔锁定
                    ↓ 从环绕到俯冲（动态转换✅）
S02 高潮（7秒）：微距推进 → 仰冲升空 → 悬浮环绕
                    ↓ 从环绕到拉远（对比✅）
S03 收束（5秒）：急速拉远 → 微距环绕 → 定格冻结
                    ↓ 从拉远到环绕（层次变化✅）
```

### 修复方案
1. 在 `nirath-master-pipeline.js` Stage-9 中实现运镜衔接检查
2. 建立运镜衔接规则矩阵
3. 自动检测冲突并调整
4. 输出运镜衔接报告
