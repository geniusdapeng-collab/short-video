## 2026-06-13 19:15 - v6.5.64-P1 双Bug修复

### 队长指令
队长要求先静心分析根因，再对症下药："你要静下心来，先仔细分析一下问题，找到关键问题所在，然后再对症下药。切不可马虎，觉得初步定位一下问题就开始快速搞一通。"

### Bug 1 分析：STAGE-6 `缺少allocations字段`
**日志**：`content=0 | reasoning=3128`
**根因定位**：
1. LLM把所有token用在reasoning上，content为空
2. STAGE-6解析代码路径：先判断 `result.content` → 空；再判断 `result.reasoning_content` → 从reasoning提取了文本但不是JSON；最后判断 `result.allocations` → undefined
3. 深层根因：LLM没有按预期输出JSON格式的时长分配，而是把分析过程放在reasoning中，结论没有以JSON格式输出到content

**修复方向**：优化STAGE-6 Prompt，强制要求LLM在content中输出JSON格式的allocations数组，或在reasoning中明确标注最终JSON结果。

### Bug 2 分析：STAGE-9 `durations.find is not a function`
**日志**：`TypeError: durations.find is not a function`
**根因定位**：
1. 在 `runPipeline` 中：`const durations = await runStage('STAGE-6', ...)` → durations 是 `stageDurationAllocation` 返回的对象 `{allocations: [...], totalDuration: 58, maxDuration: 15}`
2. 但STAGE-9调用时：`() => this.stageCameraMovement(result.stages.storyboard, result.stages.fpvDecision)` → 没有传入durations！
3. 在 `stageCameraMovement` 中，如果 `this.mode !== 'nirath'`，它调用 `this.llmEnforcer.requireLLM('STAGE-9', () => StagePrompts.STAGE_9_CAMERA(storyboard.shots || [], this.mode))` → 传入的是 `this.mode`（字符串'generic'），不是durations对象
4. `StagePrompts.STAGE_9_CAMERA` 接收参数：`function(scenes, durations)` → durations='generic'，字符串没有.find() → 报错

**修复方案**：
1. 修改 `runPipeline` 中STAGE-9调用，传入durations对象：将 `this.stageCameraMovement(storyboard, fpvDecision)` 改为 `this.stageCameraMovement(storyboard, fpvDecision, durations)`
2. `stageCameraMovement` 方法签名改为 `(storyboard, fpvDecision, durations)`
3. 在 `StagePrompts.STAGE_9_CAMERA` 中增加类型检查：如果 `!Array.isArray(durations)`，尝试从 `durations.allocations` 提取
