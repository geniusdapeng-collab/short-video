## 修正：canonical ID 统一为 `taotie`（无连字符）

### 根因发现
`beast-domain-model.js` 规范明确定义：
- canonical ID: `taotie`（小写+下划线，无连字符）
- 注释明确写"禁止连字符（tao-tie）"
- 但 aliases 包含 `tao-tie` 用于兼容查询
- `resolveCanonicalId()` 方法可将任意输入标准化为 canonical ID

### 初始修复错误
第一次修复时把硬编码示例改成 `tao-tie`（带连字符），方向错误。

### 正确修复方向
统一使用 canonical ID `taotie`：
1. `nirath-master-pipeline.js` LLM prompt 示例：`"characters":["xiaoG","taotie"]`
2. `pipeline-integrity-validator.js` aliases：`taotie: ['饕餮', 'tao-tie']`
3. `normalizeCharId` 映射函数：`tao-tie` → `taotie`
4. 输入文件 `stories/taotie-ep01-input.json` 中 `id: "tao-tie"` 可通过 `resolveCanonicalId` 映射

### 副作用修复
`characterProfiles` 出现 `"undefined, 28岁, female, "` 是因为 `characterPromptBuilder.buildMinimal` 找不到角色（ID不匹配），修复 ID 映射后恢复正常。

### 教训
看规范文件（beast-domain-model.js）比看输入文件更重要。输入文件可能用兼容别名，但系统内部必须用 canonical ID。

## 新发现问题深度根因分析（2026-06-07 11:25 GMT+8）

### 问题1：运镜未进入 Prompt（STAGE-9 失败）

**表面现象**：S01/S02/S04 运镜生成后未进入最终 Prompt，Validator 判定"运镜输出未被下游消费"。

**根因**：不是 `buildPromptV3` 没读取运镜，而是 **「末尾截断」把 `【镜头时间轴】` 吃了**。

1. `buildPromptV3` 正确注入 `【镜头时间轴】`（日志：`91字符 | 独立字段追加`），但注入位置是 **prompt 末尾**
2. `prompt.length > 980` 时触发 `smartTruncate`（buildPromptV3 内部）和 `smartTrim`（stageRender 中），两者都是**从末尾截断**
3. `smartTruncate` 的逻辑是 `prompt.substring(0, maxLen - 3)`，虽然声称"保护核心字段"，但它只保护"截断点落在字段内部"的情况。`【镜头时间轴】` 在末尾、完全在截断范围之外，直接整段丢失
4. `stageRender` 中的 `smartTrim` 更离谱：它传入的是 `enhanced.prompt`（原始 prompt），把前面刚注入的照明方案、场景化环境、情绪增强全部忽略，重新裁剪原始 prompt。而且它的"优先保留核心区块"逻辑中，如果核心区块总长度 > 980，后面的区块（`【镜头时间轴】`）直接跳过

**结果**：S01/S02/S04 的 `【镜头时间轴】` 被截断，Prompt 中不含 `progressive_reveal`/`dawn_break` 等关键词，Validator 判定"运镜未消费"。

**修复方向**：将 `【镜头时间轴】` 从 prompt 末尾移到高优先级位置（如 `【视觉】` 之后），或修改 `smartTruncate`/`smartTrim` 的截断逻辑确保 `【镜头时间轴】` 始终保留。

**涉及文件**：`orient-primordial-core-v24.js`（buildPromptV3 注入位置）+ `nirath-master-pipeline.js`（smartTrim 调用）

### 问题2：referenceImages 注入未生效（Stage 10.5 报告）

**表面现象**：Stage 10.5 报告 `5/5 个含角色镜头未绑定定妆照`。

**根因**：**时间顺序错误——Stage 10.5 检查 Stage 11 才会注入的数据**。

1. `validateCharacterReferences` 在 `stageSafetyGate`（Stage 10.5）中调用，检查 `shot.referenceImages` 或 `shot.content` 中是否有 `role: 'reference_image'` 的项
2. 但 `referenceImages` 注入代码是在 `stageRender`（Stage 11）中执行的：

## 火山引擎官方 Seedance prompt 字数建议（2026-06-07 21:11 GMT+8）

**来源**：火山引擎方舟平台官方 API 文档 `https://www.volcengine.com/docs/82379/1520757`

**官方原文**：
> 提示词字数建议：中文提示词不超过 500 字，英文提示词不超过 1000 词。字数过多易导致信息分散，模型可能忽略细节、仅关注重点，进而造成视频缺失部分元素。

**关键判断**：
- 这不是 API 硬限制（超了不会报错），而是**效果最佳实践建议**
- 当前系统 980 字符硬上限 → 对纯中文约 500 字基本够用
- 但我们的 prompt 是**中英混合**（hyper-realistic、cinematic、panoramic 等），实际信息量远超纯中文 500 字
- **队长判断正确**：太长 → 注意力分散；太短 → 效果出不来

**建议优化策略**：
- 不放宽长度限制，而是**提升单位字符信息密度**
- 压缩英文术语：`hyper-realistic cinematic ultra-detailed` → `超写实电影级`
- 砍掉重复修饰：`vast magnificent epic breathtaking` → `史诗级`
- 优先保留硬约束：角色锚点、运镜、时间轴、负面约束不可丢
- 风格词后置截断：画质/风格词可适度精简，核心叙事前置
