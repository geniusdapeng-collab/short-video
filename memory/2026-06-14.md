

### v6.6.3 发布：Stage 6 时长分配系统修复（10:46-10:50）
**问题**: Stage 6 时长分配中，当 V2 计算值 > PRD 值时，系统强制使用 PRD 值，导致台词语速过快（如 S05：61字/5秒 = 12.2字/秒，远超舒适语速4.5字/秒）
**根因**: 系统设计假设 PRD 的 duration 是"业务定义"，必须优先遵守。但 PRD 的 duration 是输入时就定死的，没有根据实际台词字数自动调整
**修复方案**（v6.6.2-fix）:
- 当 V2 > PRD 且 V2 ≤ 15秒（Seedance硬约束）→ 使用 V2 值（内容适配）
- 当 V2 > 15秒 → 使用15秒（硬约束），提示精简台词
- 当 V2 < PRD → 保持 PRD（业务定义优先）
**关键约束**: 15秒是系统级硬约束（Seedance单次渲染上限），不可突破
**修复效果**: S05 从 5s（语速12.2字/秒）→ 10s（语速4.3字/秒，舒适）
**文件修改**: `systems/nirath-master-pipeline.js` + `zhuoyue-system/core/nirath-master-pipeline.js`
**发布状态**: ✅ GitHub推送完成
